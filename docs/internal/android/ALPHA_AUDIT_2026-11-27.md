# Android alpha audit, 27 November 2026

The public alpha has a working distribution and substantial native playback coverage. Three user journeys need attention first. Playing from a large library can fail, a failed seed change can start Radio from the previous song, and a partial server outage can hide the library and settings. Recent web navigation changes also left saved artists and albums without a browsing destination on Android.

## What was checked

The isolated checkout started at `origin/main` commit `e67e4941`. The Spanish download page served the public APK from `1adcdf19` at the time of the audit. The newer release workflow was running. The native Android source tree was identical between the two commits. The Android bundle had received changes, including a shared Release Radar loader and loading placeholders.

## Findings in priority order

| Priority | Finding and evidence | Correction and acceptance case |
| --- | --- | --- |
| High | **Tapping a song in a large library can fail to start playback.** With 1,001 eligible local songs, tapping the first visible row submitted a single queue of 1,001 tracks. Media3's service calls a Kotlin validator that rejects over 1,000 rows or over 256 KiB of serialized metadata. Rich metadata can hit the byte limit earlier. [Library row activation](../../../ui_web/src/mobile/LibraryBrowser.tsx), [queue conversion](../../../ui_web/src/lib/program/tracks.ts), [native limit](../../../android/app/src/main/java/com/soundsible/android/ProgramQueue.kt), [service command](../../../android/app/src/main/java/com/soundsible/android/PlaybackService.kt) | Keep the bounded bridge. Send a window around the selected occurrence and provide continuation, or let the service resolve the context. Exercise the first, middle and last song, duplicates and the byte limit independently. |
| High | **Radio can use the wrong seed.** With an existing programme, searched for a different recording, chose Start radio, let resolution succeed, then rejected only the replacement queue command. The APK still issued a radio command with the old queue token and occurrence key. The parent play function consumes the rejection and the radio action reads whichever programme is current. [Android player](../../../ui_web/src/mobile/AndroidStart.tsx), [catalogue action](../../../ui_web/src/mobile/catalogActions.ts) | Require confirmed replacement and seed identity before starting Radio. A rejected replacement or a target-device change must leave the old programme alone. |
| High | **A failing secondary resource can hide the connected app.** On cold start with no offline copies, account, library and bookmarks succeeded. Returning 503 only for downloader status produced two retry controls and no library, settings or primary navigation. The account refresh commits everything after one `Promise.all`, then the shell gates navigation on that snapshot. [Refresh and shell](../../../ui_web/src/mobile/AndroidStart.tsx) | Render the confirmed collection and handle download/bookmark failures on their own surfaces. Preserve account-reset behavior for a genuine 401. Exercise partial failure on first load and on refresh. |
| Medium | **The empty playlists screen has no create action.** The packaged UI showed tabs and the empty-state text. The command is rendered in a toolbar reachable once a playlist is open. The song menu provides an alternative through Add to playlist. The web playlists screen exposes Create immediately. [Android list](../../../ui_web/src/mobile/LibraryBrowser.tsx), [web list](../../../ui_web/src/routes/Playlists.tsx) | Put Create in the playlist landing toolbar and test creating the first empty playlist from that screen. |
| Medium | **Android can bookmark entities but gives them no destination.** It fetches saved entities, marks matches in Discover and offers save/remove. Its navigation and library tabs expose no list of bookmarked artists or albums. On web, Home shows both and Bookmarks supports browsing and filtering. A user who bookmarks a catalogue-only album on Android has to find it again. [Android shell](../../../ui_web/src/mobile/AndroidStart.tsx), [entity marks](../../../ui_web/src/mobile/entityMarks.ts), [web Home](../../../ui_web/src/routes/Home.tsx), [Bookmarks](../../../ui_web/src/routes/Bookmarks.tsx) | Share the bookmark list presentation and inject navigation and actions. Verify that a saved album with zero acquired tracks opens from the list on both clients. |
| Medium | **Release Radar loses the reason for a refresh.** Core emits `reason: new_releases` and a timestamp. The Android socket bridge forwards only the event name and generation. Android dispatches an empty object to the shared loader, which accepts an untyped event only while awaiting revalidation. With a settled shelf, the packaged UI made one initial read and no second read after the native event. Web preserves the payload. [Core event](../../../shared/api/routes/discovery_feed.py), [Android bridge](../../../android/app/src/main/java/com/soundsible/android/EnginePlugin.kt), [shared loader](../../../ui_web/src/lib/newReleases.ts), [web event handling](../../../ui_web/src/stores/runtime.ts) | Carry the typed reason and timestamp through Capacitor. Test both a settled shelf receiving a release update and an unrelated discovery notification. |
| Low | **The signed alpha labels itself as an unpublished development build.** Its library displayed “Development build: not a release yet.” The notice is unconditional and translated into all four supported languages. [Library notice](../../../ui_web/src/mobile/LibraryBrowser.tsx) | Gate the notice on the build channel or remove it. Check the visible library on the public release variant. |

## Shared code and performance

- **Favourites already has a shared index.** Android calls the linear saved-entry lookup for every row when filtering Favourites or sorting favourites first. With 5,000 tracks and 5,000 saved entries, three desktop Node runs of the actual helpers returned the same 1,250 favourites. The linear path took 204–210 ms. Building and querying the existing index took 1–5 ms. These are helper timings on the audit machine. Build the index once per saved snapshot on Android as the web store does. [Android lookup](../../../ui_web/src/mobile/AndroidStart.tsx), [list filter](../../../ui_web/src/mobile/LibraryBrowser.tsx), [shared implementation](../../../ui_web/src/lib/saved.ts), [web usage](../../../ui_web/src/stores/identity.ts)
- **The two library search screens already call the same ranking function.** Web passes the artist collection and displays artist destinations. Android supplies an empty artist array and keeps only track results. Searching an artist in Songs can therefore find their recordings while omitting the direct artist result. Reuse the result model with an Android navigation callback. [Android search](../../../ui_web/src/mobile/LibraryBrowser.tsx), [web search](../../../ui_web/src/routes/Library.tsx), [shared ranking](../../../ui_web/src/lib/librarySearch.ts)
- **Background refresh couples unrelated work.** A visible Android screen with an active engine download polls the entire account refresh up to once per second. A foreground idle screen requests the full offline snapshot every ten seconds. On a fresh process the offline store can hash every ready file on its first state read, and the UI waits for that read before checking the online account. Subsequent reads use a modification-time cache. Measure cold startup with a realistic offline collection and refresh changed resources independently. Device latency and battery impact were unmeasured. [UI timers and startup](../../../ui_web/src/mobile/AndroidStart.tsx), [offline state and integrity checks](../../../android/app/src/main/java/com/soundsible/android/OfflineStore.kt)
- **Share behavior at the boundary where it diverges.** The clients already share row components, settings views, appearance preferences, discovery presentation and the new-releases loader. The best next candidates are saved-entity presentation, the discovery push contract and pure collection actions. Keep the account generation, offline-file ownership, media session, audio focus and native playback in their Android adapters. [Android architecture](ARCHITECTURE.md), [shared program contract](../../../ui_web/src/lib/program/runtime.ts)

Fix the three high-priority paths first. Give each an acceptance case through the shell and its adapter, then exercise a large collection on a device and repeat signed upgrade and offline acceptance before promoting the next testing milestone.
